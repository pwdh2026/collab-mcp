# 第一性原理 × 对抗性审查（工作法）

> 一句话：做重要决策/改陌生代码前，先「拆到事实→从事实推导」，再「假设自己错了→攻击最脆弱前提→换环境验证」。先证伪，再动手。

## 第一性原理（操作定义，不是修辞）
1. 剥到不可再简化的基本事实（追问：由什么构成？依赖什么前提？直到拆不动）
2. 从事实推导，不靠类比（「别人都这么做」不是理由）
3. 标注结论 vs 假设（假设单列，供人查证）
4. 用现实检验推导（对照真实对象找偏差，偏差处即风险）

## 对抗性审查（三个动作）
1. 主动证伪自己的结论（假设我是错的，找反例）
2. 攻击最脆弱的假设（推理链里最不可靠的一环，集中火力）
3. 换环境/极端输入/换通道（CI UTC vs 本机 +08 抓时区 bug；失败集合对比防「悄悄弄坏」）

## 伪定量/权威装饰文档识别清单
- [ ] 状态变量能否客观测量？（LLM 无法测自己的「稳定度」→数字是表演）
- [ ] 删掉全部公式和字样后，规则是否仍完整可执行？（站得住才是真价值）
- [ ] 「可证明」的对象是真实系统还是 toy 方程？（clamp 到 [0,1] 当然有界，空转）
- [ ] 机制是否误伤证据性反驳？（「你错了，证据是…」不应被当作高扰动手）
- [ ] 文本标注/内嵌状态是否被当作安全边界？（<STATE> 可伪造注入，文本不是边界）

## 应用时机
- 复杂/高风险/陌生代码：默认全流程（与 doubt-driven-development 同源互补）
- 普通改动：至少做「最脆弱假设」一步
- 外部项目可行性判断：先查 issue/PR 是否已被占、维护者真实态度，再决定投入
  （实证：#226 已有 3 条 PR 被关/挂起 → 放弃实现转审查，避免重复劳动）
